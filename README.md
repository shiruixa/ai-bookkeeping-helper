# 言账

**面向小微商户的自然语言智能复式记账系统**

以自然语言为唯一输入方式，将经营者的口语陈述转换为符合复式记账规范的账务数据。
**AI 仅生成结构化草稿，账务写入必须经过确定性校验与用户确认。**

## 项目简介

个体工商户、夫妻店及小微商户普遍缺乏专业会计能力，日常多依赖纸笔或移动支付账单记录收支，记录零散、口径不一，月末难以准确核算经营成果，年终复盘与纳税申报时也难以与专业会计口径衔接。现有记账软件以借贷复式记账为前提，学习成本与操作成本较高；通用 AI 记账产品又常由模型直接读写账目，缺乏人工确认，错误难以追溯。

「言账」以自然语言为唯一输入方式：经营者输入“今天卖了 580 块门锁”，系统由大语言模型完成信息抽取并生成结构化草稿，草稿经 Pydantic 结构校验、中文金额与日期确定性解析、复式借贷平衡校验后进入待确认状态，经用户确认后方写入账本。

系统底层采用 Beancount 实现复式记账，可生成利润表、资产负债表与试算平衡表，并支持月末盘存结转销售成本。账本以纯文本 `.bean` 保存，可直接交由会计使用。

系统遵循“AI 永不直接落账”原则：模型仅执行一次信息抽取，后续校验、记账与报表生成均由确定性代码完成。因此系统可在较小参数模型或本地部署模型上运行，成本较低，数据不出本机。

## 核心设计：四道关卡

```
用户自然语言输入
        │
        ▼
① 大模型结构化抽取         仅执行一次，产出草稿
        │
        ▼
② 确定性校验               Pydantic 结构校验 + 中文金额/日期解析 + 借贷平衡
        │
        ▼
③ 用户确认闸门             未确认不得写入账本
        │
        ▼
④ 事务性写入               备份 → 写入 → 重载校验 → 失败回滚
```

配套机制：

| 机制 | 说明 |
|---|---|
| 复式借贷平衡 | 每笔分录自动校验，账本不会被写入不平数据 |
| 审计溯源 | 每笔分录带 `^link`，可反查原话、修改前后与取消记录 |
| 多账本隔离 | 公司 / 个人 / 测试账本，账本文件与数据库完全独立 |
| 定期盘存结转 | 月末盘点倒推销售成本，支持连续结转与冲回 |
| 分类映射记忆 | 用户确认一次“面粉→存货”，后续自动沿用 |

## 系统架构

```
前端（原生 HTML/CSS/JS，移动端优先）
        │ REST
接口层（FastAPI，20+ 接口）
        │
编排层（状态机：记账 / 查询 / 纠错）
        │
账务层（Beancount 复式记账）
        │
数据层（.bean 账本 + SQLite 流程元数据）
```

- 账本本体为纯文本 `.bean` 文件，可独立备份、直接交由会计使用
- SQLite 仅存储聊天记录、分类映射、确认草稿与审计记录
- 所有写操作均经过“备份 → 写入 → 重载校验 → 失败回滚”

## 关键技术实现

1. **账务内核**：Beancount 以正负号表示余额方向；所有写入经加载器重新校验，失败回滚；删除采用冲销分录。
2. **意图路由**：区分记账、查询、纠错、建账与闲聊，查询与写入分离。
3. **结构化输出**：`response_format=json_object` + Pydantic 枚举校验，非法字段直接拒绝。
4. **Few-shot 与动态日期**：提示词内置示例，日期以 `{today}` / `{yesterday}` 占位并在运行时替换。
5. **上下文注入**：当天日期与用户确认过的分类映射写入 system prompt。
6. **确定性解析**：中文金额（“三百五”→350、“12块5毛”→12.5）与中文日期由正则和状态机解析，不经过模型。
7. **审计溯源**：分录携带 `^link`，审计表记录原话、操作类型、解析结果与状态。
8. **多账本隔离**：`data/books/<book_id>/` 独立存储，请求通过 `X-Book-Id` 切换。
9. **成本结转**：定期盘存法，支持连续结转与冲回。
10. **部署**：PyInstaller 打包为单文件可执行程序，数据与配置保存在程序同目录。

## 快速开始

### 环境要求

- Windows 10/11
- Python 3.11+（开发环境为 3.12.9）

### 启动

```cmd
cd /d <项目目录>

REM 1. 创建虚拟环境并安装依赖
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r backend\requirements.txt

REM 2. 配置模型
copy backend\.env.example backend\.env
REM 编辑 backend\.env，填写接口地址、API Key、模型名

REM 3. 启动
.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --app-dir backend
```

浏览器访问 `http://127.0.0.1:8000`。也可直接双击 `start.bat`。

### 模型配置

项目使用 OpenAI 兼容接口，更换平台只需修改以下三项：

```ini
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_API_KEY=<你的 Key>
MODEL=deepseek-flash
```

启动后亦可在页面“设置 → API 设置”中修改，并点击“测试连接”验证。

## 同类项目对比

[EasyAccounts](https://github.com/QingHeYang/EasyAccounts) 是一款成熟的开源中文记账软件（2021 年至今），支持 Docker 部署，内置智能助手“小易”，通过 Tool Call 提供账户查询、记账、改账、报表导出等工具，并支持 MCP 与图片识别。它是本项目重要的参考对象。

> 说明：本项目未使用 EasyAccounts 的任何代码，以下仅作同类产品思路对比。

| 维度 | EasyAccounts / 小易 | 言账 |
|---|---|---|
| 目标用户 | 个人 / 家庭 | 个体户 / 小微商户 |
| 账务内核 | 账户 + 收支 + 分类的流水记录 | 标准复式记账（Beancount），借贷平衡自动校验 |
| AI 的角色 | 通过 Tool Call 直接操作数据 | 只产出结构化草稿，人工确认后才落账 |
| 可审计性 | 备注标记 `#AI记账` | `^link` 双向溯源：原话 ↔ 分录 |
| 报表 | 收支统计、分类分析 | 利润表 / 资产负债表 / 试算平衡表 / 明细账 |
| 数据形态 | 关系型数据库 | 纯文本 `.bean`，可直接交由会计 |
| AI 能力侧重 | Agent 多工具编排、MCP、图片识别 | 结构化抽取 + 确定性校验 + 确认闸门 |
| 交互门槛 | 对话式 | 双视图：会计看报表，店主看流水 |
| 部署 | Docker Compose | 本地 Python / 单文件可执行程序 |

两种设计面向不同场景：EasyAccounts 面向“自己看得懂账”的个人与家庭，AI 直接记账更为便捷；言账面向“账目需交由会计、需支撑纳税申报”的小微商户，因此将“AI 不直接落账”和“每笔可追溯”作为硬约束。Agent 工具调用适合查询类场景，抽取式与确认闸门适合写入类场景，两者可以互补。
